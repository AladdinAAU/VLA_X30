1 Overall Architecture

Jueying X30 Pro is equipped with the motion host and the perception host internally, and
the intelligent controller on its back has the navigation host built into it. The development
host can be connected to each host of the robot through a wireless router. Each host has
been configured with the relevant commonly-used software and drivers.

2.3 Logging Function

Jueying X30 Pro generates three types of log files during motion:
Event log (.log): Record each event during the running process. The file is stored in
/home/ysc/jy_exe/log directory and can be opened from the file directory in the left
column of MobaXterm.
Operation log (.csv): Press the [Save Data] button on the Settings page of the controller
APP to save the motion state data recorded within the last 5 minutes, with the recording
frequency of 200Hz. The data saved every time can be viewed directly in Microsoft Excel.

                                 9 / 69
                           DEEPRobotics

The file is stored in the same folder as the fault snapshot. The specific path is
/home/ysc/jy_exe/data/, which can also be obtained at the end of the event log.
Fault snapshot (.snapshot.csv): Press the [Save Data] button on the Settings page of the
APP to save the fault snapshot (that is, the data within the last 5 minutes), which takes 9
seconds to save. The file is stored in the same folder as the operation log. The specific path
is /home/ysc/jy_exe/data/, which can also be obtained at the end of the event log.

  [Notes] The event log is stored for 7 days (that is, 168 hours). Every time the program is run, the
  expired logs are cleaned up to prevent the hard disk space is not sufficient.
  [Notes] When pressing the [Save Data] button, please ensure that the robot is lying down.

3 Navigation Host

Jueying X30 Pro intelligent controller has the navigation host built into it, which is
responsible for mapping, localization, and navigation. The directory /home/ysc/jy_cog in
navigation host contains the following algorithms, drivers, applications, logs, startup
scripts, and profiles related to the perceptive functions, with a directory structure as
follows(in newer versions, broker has been renamed robot_server ):

Among them, the /jy_cog/system directory contains the folders named conf, scripts, and
map. The folder conf stores the profiles which can be used to configure the system modes,
function parameters, etc; the scripts folder stores the script file; the map folder stores the
maps.

3.2 Autorun Configuration

You can set the self-start of the localization and navigation program in the autorun_slam
file in the jy_cog/system/conf directory. If the file content is set to false, then after the
robot is turned on, the localization and navigation program will not automatically run,
and you need to start it manually. This applies to the deployment of map; If the file
content is set to true, then after the robot is turned on, the localization and navigation
program will automatically run. After you provides the initial localization, the robot can
automatically run according to the deployed map and navigation tasks. The autorun
configuration takes effect after the navigation host restarts.

  [Notes] Before starting mapping, please follow the remote connection procedure to connect to host
  106 and enter: dpkg -l slam in the terminal to check the version of the slam package. The map

1. During mapping, please do not manipulate the robot for strenuous exercise and do not
    block the laser radar, otherwise the mapping may fail.

    computing resources. If any other program uses too many computing resources, enter
    the following command line to close it: sudo kill [PID].

3. Make sure the mapping program is not running. If it is running, please save the map
    and exit the program first according to 3.3.2.1. Make sure the navigation program is not
    running. If it is running, please enter the following command line in the terminal to kill
    it:

          1 bash ~/jy_cog/system/scripts/kill_nav.sh

4. Before starting the mapping program, it needs to check if there are created maps in
    the /jy_cog/system/map folder. After the mapping program starts, this folder will be
    emptied. If necessary, please move the created maps to another folder in advance and

3.3.2 Single-Floor Mapping

3.3.2.1 Start the Mapping Program
  [Notes] This version of mapping program is suitable for the indoor scenes with an area not more
  than 200m×100m.
  [Notes] Please start the mapping program when the robot is standing.

1. Open the terminal, then enter the following commands to start the script of mapping:

          1 cd ~/jy_cog/system/scripts
          2 bash start_mapping.sh

2. After starting the mapping program, please first keep the robot standing still for 5-8
    seconds, then remotely control the robot to walk at constant speed smoothly and
    steadily in the area that needs to be mapped. During scanning, you can check whether
    the localization of robot is normal and whether the point cloud is drifting in RViz.

    to preview the grid-based map during mapping, please enter the following commands
    in a new terminal:

         1 cd ~/jy_cog/system/scripts

3.3.3 Indoor Multi-Floor Mapping

  [Notes] Please start the mapping program while the robot stands still.
  [Notes] The start_mapping.sh script for single-floor mapping is not used to start the multi-floor
  mapping, because this script will start to create the point cloud map and grid map together, while
  the multi-floor needs to start the two mapping programs separately.
1. Open the terminal and enter the following command to open the point cloud program:

         1 bash ~/jy_cog/slam/scripts/mapping.sh indoor true livox

       [Notes] The parameter true at the end of the command indicates that RViz needs to be
       enabled. If RViz does not need to be enabled, it can be changed to false.
       [Notes] The point cloud map program started by this command must be kept until all floors
       are completed. Do not start and stop this program at the same time as the following grid map
       program starts and stops.
2. Please keep the robot standing still for 5~8 seconds after starting the point cloud
    program.
3. Whenever you arrive a new floor, you need to open the program to generate the grid
    map and name the map:

         1 bash ~/jy_cog/slam/scripts/occupancy_mapping.sh gridmapName

    A parameter is carried at the end of the command, separated by a space from the
    command, indicating the file name of the grid map that is being generated for this new
    floor. When you need to generate multiple grid maps, you need to specify a different
    file name for each grid map.

       [Notes] It is recommended to name the map jueying, which is the startup layer for naviagtion
       because the grid map with the name jueying is loaded by default when the navigation starts.

                                                                             18 / 69
                                                                        DEEPRobotics

       [Notes] The grid map can only be generated when the point cloud program is running.
4. When the program to generate the grid map is running, user can control the robot to

    scan the environment of the floor. When finishing scanning this floor and arriving at
    the next floor, press Ctrl+C to quit the program of generating the grid map, and the
    grid map of this floor will be automatically saved. Then open the grid map program
    again in place (note that the map file name is specified and is not repeated), you can
    start to scan the next floor.

       [Notes] It is recommended to close and restart the grid map program in the area connecting
       the two floors and ensure that the area is accessible on both two grid maps.
5. After scanning all floors, press Ctrl+C to exit the grid map program and the point cloud
    map program, and both the grid map of the last floor and the complete point cloud
    map are automatically saved.

3.3.5 Modification of Grid Map

If the grid-based map does not fully match the actual environment, or it needs to
manually define the passable areas, you can use GNU Image Manipulation Program to
modify the .pgm file: Right-click the .pgm file, select Open with Other Application, then
select GNU Image Manipulation Program, and click Select.

                                                                             20 / 69
                                                                        DEEPRobotics

If the toolbars of GNU Image Manipulation Program are not displayed, click Tab key to
display them.
The toolbars provide the tools of foreground color and background color, foreground
color sets the color of the Brush tool, and background color sets the color of the Eraser
tool. In the grid-based map, the black area represents the obstacle, that is, the impassable
area. The white area represents the passable area, and the gray area represents the
unknown area. You can use the Brush tool or the Eraser tool to add or erase the black
areas. Press and hold the Shift key, then left-click to draw the straight line, or press and
hold the Ctrl key, then left-click to suck up the color.

  [Notes] If the map is multi-floor, it is important to ensure that the transition area between the
  two connecting floors is accessible from both two grid maps. If stairs or slopes are present in the
  map, they may be identified as obstacles and displayed as black in the map. When editing the
  map, the accessible area of the stairs or slope should be modified to white.
After the modification, select File - Overwrite jueying_map.pgm in the upper menu bar to
overwrite the original file (do not choose File - Save to save the file). When the software is
closed, the save prompt will pop up again. At this time, just click Discard Changes.

3.4 Map Deployment (for v2.1.0 and later)

This version's mapping function will simultaneously construct point clouds and 2D grid
maps. For multi-floor scenarios that require multiple grid maps, you need to specify them
manually when the floors change. The mapping program in this version supports map
construction for single-floor small indoor scenes (50m×50m), multi-floor small indoor
scenes (50m×50m×10 floors), and single-floor large scenes (500m×500m).

3.4.1 Notice for Use

1. During mapping, please do not manipulate the robot for strenuous exercise and do
     not block the laser radar, otherwise the mapping may fail.

2. Before mapping, open the terminal and enter the top command to check the

                                                                             22 / 69
                                                                        DEEPRobotics

     computing resources. If any other program uses too many computing resources, enter
     the following command line to close it: sudo kill [PID].

3. Make sure the mapping program is not running. If it is running, please save the map
     and exit the program first according to 3.4.3. Make sure the navigation program is not
     running. If it is running, please enter the following command line in the terminal to
     kill it:

          1 bash ~/jy_cog/system/scripts/kill_nav.sh

4. Currently, the mapping for mixed indoor and outdoor scenes, smooth tunnels,
     smooth long corridors, relatively open scenes (depending on the radar model), high

     distance scenarios without loops (or with few loops) venue is not supported.

3.4.2 Function Introduction

This version of the mapping program includes three mapping modes:
1. fast: Quickly construct point clouds and grid maps (including multi-floor grid map

     construction, but without loop detection and keyframe map generation).
2. indoor: Construct point clouds and grid maps for indoor multi-floor, narrow, or small-

     scale scenarios (including loop detection and keyframe map generation).
3. outdoor: Construct point clouds and grid maps for large, relatively open outdoor

                                                                             23 / 69
                      DEEPRobotics

scenarios (including loop detection and keyframe map generation).

The mapping program in this version will create a new file for each 3D point cloud map

corresponding to a scene under the /home/ysc/jy_cog/system/maps directory. The folder

is named using the format [CustomName]-Date-Time, and it contains a complete point

cloud map (jueying.pcd), the default grid map (jueying.pgm), and a parameter file

( jueying.yaml). If there are multiple grid maps for the same scene, they will be named with

the prefix jueying, followed by a sequential number starting from 1, such as jueying1

(while still retaining jueying.pgm and jueying.yaml). Additionally, keyframe maps

(including point clouds of keyframes and their pose files) may be stored in the details

folder.

The localization and navigation program will by default call the map located in the

/home/ysc/jy_cog/system/map directory. The map folder is a symbolic link pointing to a

specific map folder. If you need to change the address that the symbolic link points to,

you can delete the original map folder and then follow the command below in the

terminal to proceed:

1 cd ~/jy_cog/system  #enter the directory (optional)

2 ln -s maps/[folder name] map # Replace the [folder name] according to the actual situation. This

command creates a symbolic link named map, pointing to a specific folder under the maps directory.
